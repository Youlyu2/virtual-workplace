# 绘图开销与验证边界

场景通过 AppKit/Core Graphics 绘制。0.9.4 的控制窗口/全屏以30fps调度，桌面背景每屏15fps；一次绘制会提交整幅场景，因此多屏、主窗口和系统设置预览同时可见时，绘图与合成开销会叠加。持续动画的累计 GPU 时间也会随运行时长增加，需与实时百分比区分。

## 已完成的庭院优化

晴天白昼的庭院不需要天气调色或降水，但旧实现仍先创建两次全幅 RGBA 裁切。现在直接跳过没有绘图内容的裁切；需要调色或降水时共用一次原有遮罩。没有降低帧率、减少角色动作或改变原素材格式。

72组庭院旧算法逐像素对比通过，覆盖天气、昼夜、Retina、宽屏、镜像与屏幕偏移；120组优化前后场景哈希相同。

同一合成场景、每组300帧的离屏测量：

| 庭院条件 | 修改前 CPU 毫秒/帧 | 修改后 CPU 毫秒/帧 |
| --- | ---: | ---: |
| 晴天白昼 | 7.15 | 3.78 |
| 雨夜 | 23.51 | 17.46 |

上述分别约减少47%和26%的庭院绘制 CPU 耗时；**不能解释为整款应用的 CPU 降幅，更不能换算为实时 GPU 百分比下降**。实时 GPU 需要在解锁、相同窗口和显示器布局下分别采样。当前尚未完成该现场对比。

