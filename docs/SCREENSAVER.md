# Mac 屏保构建与诊断

项目提供独立主应用和真正的 `.saver` 屏保，两者使用同一个原生场景渲染器。目标为 macOS 26、Apple Silicon。本仓库发布源码，本地构建使用 ad-hoc 签名；自行构建不需要付费开发者账号。

当前使用全屏像素小屋与原生实时信息图层。系统设置里通常显示文件名“VirtualWorkplace”，位于“Other”分类，可能需要点“Show All”。验证范围见 [验证说明](VALIDATION.md)。系统设置可能缓存已加载插件；安装文件更新不代表实际运行的宿主已重新加载，排查见文末。

在主应用「屏幕场景 → 系统屏保」单独设置每块屏幕。桌面默认各屏都显示房间；屏保默认主屏房间、其他屏幕窗外，并保留相邻场景的边缘衔接。天气与昼夜共用。屏保直接读取快照里的 `world.screenSaverDisplayScenes`，桌面配置独立。小尺寸系统设置缩略图固定显示房间；门外访客只出现在户外背景，不能用房间缩略图验收访客。

## 构建与安装

```sh
./scripts/build.sh
./scripts/test.sh
./scripts/install.sh
open "$HOME/Applications/虚拟工位.app"
```

屏保安装到当前用户的 `Library/Screen Savers/VirtualWorkplace.saver`，无需管理员权限。已有同 bundle ID 的包会备份到 `Library/Application Support/VirtualWorkplace/Backups`；遇到同名但不同 ID 的包会停止，不覆盖其他程序。

应用的「安装屏保」按钮现在会实际安装或更新用户级屏保，并校验 bundle 信息、关键资源与签名。已有本项目屏保会备份；失败会保留或恢复旧版。安装成功会显示结果和后续选择步骤，不再仅因为目标文件存在就跳到墙纸设置。安装包内携带匹配版本的 `.saver`，单独复制 `.app` 也可以安装屏保。

在系统设置的「墙纸」里点击「屏幕保护程序」，进入「其他」分类，必要时点「显示全部」，选择 **VirtualWorkplace**。安装成功弹窗可直接打开屏保设置或在 Finder 中显示已安装文件。若选择器仍使用旧版本，退出并重新打开系统设置。安装操作和脚本均不更改当前屏保、锁屏密码或休眠设置。

选择界面名称以系统实际显示为准，插件文件名为 VirtualWorkplace。Apple 的设置路径说明见[屏保设置](https://support.apple.com/en-gb/guide/mac-help/mchlp1227/mac)。

安装流程可用 `./scripts/test-saver-install.sh` 单独验证。测试只在独立临时目录操作，覆盖新装、更新、嵌入包优先、备份、签名失败保留、最终验证失败回滚、不同应用同名文件保护、符号链接保护及资源缺失拒绝。

卸载用 `./scripts/uninstall.sh`，只删除本项目的两个已安装包，保留场景状态与备份。若当前选中了本屏保，请在系统设置改选其他屏保。

## 状态与生命周期

- 主应用是唯一状态写入者，每个屏保实例只读真实用户 home 下的 `Library/Application Support/VirtualWorkplace/state.json`，每秒最多读取一次。
- 0.8.0起，快照还携带门外待办。户外背景显示访客、摘要与等待时间，室内窗玻璃不重复绘制；屏保只读这些记录，不负责创建note、复制或交办。待办操作在主应用「门外待办」面板完成，原始记录独立保存在pending-notes.json，离线不会让待办消失。
- 0.9.0起，屏保与应用用相同规则从最旧待办的原创建时间推导当前天气；默认1小时转阴、2.5小时下雨、4小时雷雨，基准天气仍保存在world中。闪电事件由共享绝对时钟决定，减少动态效果时停用；不增加额外天气计时器或网络请求。
- 屏保不启动模拟器、不写状态、不操作 Codex。所有屏幕读取相同快照，布局按实际显示器计算；仅640×480以内且标为预览的正尺寸缩略图固定显示房间，完整视图即使被宿主误标为预览仍使用屏保配置。
- 关闭主应用窗口可以保留主进程；彻底退出主进程后不再更新任务状态，场景按共享模型的超时规则显示离线。
- 文件缺失或损坏时保留最后有效场景；初次无状态时使用内置空场景。后续成功读取会自行恢复。
- 仅在系统请求播放、窗口可见、视图未隐藏且显示器未休眠时启动系统动画计时器。系统远程屏保窗口可能缺少 AppKit 的可见遮挡标志；已挂载且在当前空间的这类窗口按系统启动请求处理。停止、隐藏、离开窗口、熄屏时停止，恢复后重置帧间隔。
- 遵循系统「减少动态效果」设置。熄屏和电脑睡眠不等于屏保；本程序不自动阻止睡眠。

## 真实屏保验收

可先运行 `./scripts/diagnose-saver.sh` 验证真正 `.saver` 的主类加载、离屏绘制与停止动画，并生成 `build/saver-diagnostic.png`。加 `--window` 会短暂显示一个独立测试窗口，验证十次启动/停止、隐藏/显示、模拟熄屏/唤醒、关闭窗口共 25 项生命周期检查，不锁屏、不切换系统屏保。

运行 `./scripts/diagnose-saver.sh --state-roundtrip` 还会在独立临时状态目录下启动另一个写入进程，验证屏保依次读到 `1 → 3 → 0` 个任务。这个测试隐含可见窗口测试，全程不读写主应用的实际状态文件。测试宿主没有系统屏保沙箱，不能替代后续真实验收。

Mac 已锁定或没有可见桌面时，运行 `./scripts/diagnose-saver.sh --headless-roundtrip`。该模式不显示窗口，也不放宽生产环境的可见性判断；它在真正的屏保 bundle 内显式调用只读诊断轮询，由另一个进程更新独立临时快照，验证 `1 → 3 → 0` 个任务并分别输出 PNG。它还验证损坏 JSON 保留最后有效的 3 个任务、旧心跳解析为离线，并输出对应 PNG；非预览屏保实例在两套配置相反时只跟随屏保配置。整个测试不能显示窗口或启动动画计时器。

无界面测试通过仅说明 bundle 加载、跨进程状态读取、离线/损坏处理与原生离屏绘制通过。可见动画生命周期、真正系统沙箱、真实锁屏和多显示器必须保留为未验证，待用户解锁后再执行前述测试。

1. 先在主应用增减模拟任务，确认三种动作、屏幕数量、任务状态切换正常。
2. 在系统设置预览本屏保，确认它绘制完整场景，并与主应用最新任务一致。
3. 启动主应用中的自动演示，然后通过当前系统设置的空闲规则进入屏保。观察屏保中屏幕会随演示增加、减少，状态更新目标为 2 秒以内。
4. 如需要验证锁屏，由用户手动锁屏。确认画面仍能读取最新模拟状态；解锁后验证停止动画日志。测试不关闭密码要求，也不自动锁用户屏幕。
5. 连续进入、退出屏保五次，检查是否留下持续渲染的实例。将主应用退出后再次进入屏保，确认离线显示；重新打开后确认恢复。
6. 如连接外屏，分别在两个显示器选择本屏保，检查不同分辨率下布局、两屏任务一致、接拔显示器后正常恢复；单显示器结果不能作为多屏通过。

macOS 的屏保宿主可能存在预览标志、重复实例或多屏生命周期问题，所以独立窗口预演不能代替以上验收。遇到系统宿主问题时记录证据，不强制终止系统宿主。

## 日志与问题定位

```sh
log stream --style compact --level info --predicate 'subsystem == "com.virtualworkplace.screensaver"'
```

日志只在创建、状态读取失败/恢复、在线状态变化和动画启动/停止时输出。首次创建会打印实际读取路径。对照主应用状态文件，确认屏保没有错误地读取沙箱容器里的另一个 `Application Support`。

0.2另外提供去重的生命周期日志，包括start/stop入口、窗口挂载、动画是否获准、窗口可见性/occlusion与首次绘制资源状态，用于区分宿主未请求动画和窗口尚未可见。相同状态不会逐帧重复输出。

本地 ad-hoc 签名可能在直接运行 `ScreenSaverEngine` 的调试路径被库验证拒绝；真实系统空闲屏保通过 `legacyScreenSaver` 加载，二者不等价。因此不以直接运行系统引擎失败作为屏保不可用的唯一结论，也不关闭 Gatekeeper 或 SIP 来绕过问题。对外分发需要 Developer ID 签名和 Apple 公证。

### 更新后仍显示旧画面

macOS 的 legacyScreenSaver 宿主可能长期保留已经载入的旧版代码。安装成功表示磁盘上的屏保文件已更新，不代表现有宿主已经重新载入。先退出并重新打开系统设置，再选择 VirtualWorkplace；如果真实全屏仍显示旧画面，需要让对应系统宿主重新加载。本应用不会自动终止系统宿主，也不会主动重启或注销电脑。更高级的进程排查和刷新应由用户确认后进行。

预览宿主和全屏宿主可能分别缓存不同版本，必须分别验证。锁屏快捷键用于进入锁定界面；复验自动屏保时应等待自己系统设置的空闲时间。日志出现 `remoteOcclusionFallback=true` 表示远程窗口已走动画启动回退路径。新版本的独立诊断通过，也不能证明系统全屏宿主已更新。
