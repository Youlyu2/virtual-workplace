# Codex 本机与开发机实时接入

0.3.0 将真实会话与模拟演示分成两个明确来源。正常启动选择「Codex 实时」，应用窗口、桌面背景与系统屏保读取同一份场景快照；选择「模拟」或启动演示后，画面会明确标示模拟来源。断开连接不会自动退回模拟器。

本文说明实现方式与使用边界。构建、安装及实际窗口等验收结果记录在 [验证记录](VALIDATION.md)，此处不代表新增验收已经通过。

## 读取链路

1. 以只读方式查询本机 Codex 的 SQLite 会话索引，发现最近100个未归档的主会话，排除子代理会话。
2. 从桌面本地元数据读取远端线程的主机归属和主机显示名，再连接 `~/.codex/ipc/ipc.sock`，按主机ID与线程ID订阅本机及开发机会话的桌面内部状态流。初始快照与后续增量更新中的 `threadRuntimeStatus` 提供运行状态，SQLite 的修改时间不被当作运行状态。
3. 以同一完整会话ID校验SQLite中的rollout_path及日志session_meta，读取与CodeIsland同源的本地事件，补充当前阶段、工具名、最近可见进展和已知的本轮开始时间。
4. 将真实会话标识、显示标题、运行状态、执行详情和可用时间投影到 `SceneSnapshot`，由主应用写入 `~/Library/Application Support/VirtualWorkplace/state.json`。
5. 屏保只读主应用快照，不重复订阅 Codex，不运行模拟器或任务。

本机桌面使用独立的 stdio app-server，不能通过另起一个 app-server 获取它当前运行中的会话。此次适配使用已在本机验证可订阅的桌面内部 IPC，而不是另起服务推测状态。该协议不是对外稳定接口，桌面更新后可能改变；兼容失败时应显示未连接。

官方 [Codex App Server 文档](https://learn.chatgpt.com/docs/app-server) 描述了线程运行状态、状态变化通知及 turn 完成语义，可用于理解这些状态。文档中的公开 app-server 协议不等于本应用所用的桌面内部 IPC。

## 画面中的状态

| 来源状态 | 画面含义 |
| --- | --- |
| 正在运行 | 显示工作中，自动姿态进入工作状态。 |
| 等待审批或输入 | 显示等待确认，确认仍在 Codex 会话中操作。 |
| 明确失败 | 显示出错或需处理。 |
| `idle` | 当前空闲或待机，不证明任务成功。 |
| 本轮明确 `completed` | 可标为本轮完成并计入完成统计。 |
| Codex 停止、连接丢失或协议不兼容 | 显示未连接，不继续制造运行中的假象。 |

仅有 `idle` 或收到一般回复，不足以证明任务完成。完成统计以本轮明确完成结果为依据；已观察到本轮结束的会话屏保留至会话卸载。真实来源未提供百分比、下一步或完整时长时，相应信息留空或显示状态，不使用模拟器填充。

每个真实会话使用稳定标识关联屏幕。场景常驻三块基础显示器，最多同时呈现六个会话；超过六个时优先展示运行中、等待及出错等需要关注的会话，并标出来源总数。空闲基础显示器展示概览，不算作真实任务。

## 操作与范围

- 右侧「Codex 实时 / 模拟」切换任务来源；「查看模拟演示」会明确切入模拟来源。
- 实时来源为只读，应用不提供添加、关闭真实会话或修改真实状态的按钮。人物三种姿态仍可随时手动指定，选择「自动」后恢复任务驱动。
- 本机会话从最近100条索引发现；开发机会话从 Codex 桌面的主机归属提示发现，最多8台、每台32条、总计128条。仅显示桌面已加载且本应用已观察到活动的主会话，不通过历史索引猜测任务仍在运行。
- 远端需要已通过当前 Mac 的 Codex 桌面连接；应用不额外建立 SSH 连接或在开发机部署服务。独立 CLI、训练/评估进程和其他云端作业不在本适配器范围内。
- 退出本应用会释放订阅；屏保随后按心跳规则进入离线休息。关闭控制窗口则保留菜单栏和同步。
- 显示器边框、下巴、支架和底座沿用0.2.2修复，随升降桌同步移动。

首次订阅长会话可能接收一次较大的状态快照，单帧上限为64 MiB。首帧完成前可能需要等待；超限或不兼容应视为连接失败，不显示模拟任务代替。

## 数据与故障排查

读取和显示均在本机进行。本应用不上传会话内容，不读取 Codex 登录凭据，不修改 Codex 配置或 hooks，不启动或继续 Codex 任务，也不响应审批请求。内部订阅可能接收会话快照，但共享给屏保的文件只保留场景显示需要的数据。

看到「Codex 未连接」时，先确认本机 Codex 桌面已打开、目标会话在本机或已连接的开发机上运行，且右侧选中「Codex 实时」。若桌面刚升级，协议可能需要重新适配。模拟演示可以单独验证画面，但不能作为真实接入成功的证据。

系统屏保的真实锁屏持续刷新、物理睡眠/唤醒和外接多显示器验收边界沿用 [屏保说明](SCREENSAVER.md) 与 [验证记录](VALIDATION.md)，本次接入说明不扩大其通过范围。

## Island 同源执行详情（0.5.0）

已安装的 CodeIsland 使用本地Codex rollout JSONL事件获取更详细的信息，其本地socket是hook事件入口，没有可用的只读查询接口。本应用直接接入相同事件源，无需CodeIsland运行，也不修改其hook或配置。

- 在显示器和侧栏显示思考阶段、当前工具和最近一条可见助手进展；工具返回后取消当前调用标签。等待审批、错误、待机和断连始终由原有实时IPC状态决定，不用日志猜测任务是否成功。
- 只提取公开助手消息的commentary/final文本、工具名字及会话/轮次标识。工具参数、输出、推理正文和代理间消息不进入共享场景状态。阶段可由事件类型标记为思考中，不读取推理正文。
- 按完整会话ID校验日志头和轮次ID，不能将文件名额外的fork短ID当作第二个任务。新一轮清除前轮进展与工具，匹配工具call_id及返回事件，支持并行调用。
- 首次读取限制在256KiB文件头和2MiB尾部，之后按文件偏移增量更新，支持部分写入、轮换、截断和过大行恢复。不会为展示详情扫描整个大文件。
- 如果开始事件已经位于首次读取范围之外，本轮时长留空；未知时长不以文件修改时间或进程运行时间代替。日志暂时不可用只移除详情，不影响原有实时状态连接。

`diagnose-codex-live.sh --expect-details`可检查真实详情链路，`--expect-tool`等待观察到真实未返回工具调用。诊断默认只输出阶段、工具名和是否有进展/开始时间，完整的短文本仅在显式指定的项目build快照文件中保存。

## 开发机接入（0.5.3）

自动发现已保存在 Codex 桌面中的远端主机与线程归属；这些提示只提供发现线索，运行状态仍由带相同主机ID和线程ID的实时IPC提供。远端详情来自桌面已有的 canonical/legacy 会话状态流，按有序回合选择当前轮，补充公开助手进展、工具名和真实轮次开始时间。不会读取SSH凭据、建立新连接、安装远端代理或触发任务。

本机保留原始线程标识；远端使用主机摘要与线程ID组成稳定的场景标识，避免不同开发机上同一UUID占用同一屏幕。屏幕和侧栏显示主机来源，任务标题保持原样；等待确认、失败和完成规则与本机一致。启动时的历史已完成/待机会话不当作当前工作，只有已观察到活动的会话结束后保留状态屏。

单个远端订阅丢失或首帧超时会移除其运行声明，保留本机和其他有效订阅。整个 Codex 桌面断开时才使整份来源离线。这里同步的是 Codex 桌面持有的会话状态；当前内部 IPC 未暴露 SSH 连接状态查询，owner 仍存在也不能单独证明远端网络在线。物理断网后的状态失效速度尚未实测，使用时需保持 Codex 的开发机连接。远端状态与其他场景数据一起原子写入共享快照，因此背景和屏保读取同一结果；不增加屏保进程的网络连接。

验证：`./scripts/test-codex-remote-index.sh`、`./scripts/test-codex-stream.sh`、`./scripts/test-codex-live.sh`。实际只读探测可用：

```sh
./scripts/diagnose-codex-live.sh --observe-only --expect-host 'HOST_ID' --expect-thread UUID --expect-details
```

`--observe-only`允许验证真实待机会话，不启动或恢复任务，报告仅含来源、状态及详情是否可用，不输出助手正文。正常诊断模式仍要求目标任务处于运行或等待状态。
